KIMinder360 Mobile App

Schedule & Milestones

The development of KIMinder360 follows a structured, milestone-based schedule aligned with the Northern Arizona University Spring 2026 semester, spanning approximately four months from January 2026 to May 2026. This 16-week timeline ensures organized progression, iterative refinement, and timely completion of core features, including data storage, user customization, notification delivery, and risk mitigation. The plan prioritizes foundational elements like the database and notifications early on to allow adequate time for refinement, while integrating safety features mid-project. Breaks, such as Spring Break, are accounted for in the calendar but do not alter the milestone structure. By adhering to this roadmap, we aim to deliver a fully functional, tested, and scalable app by early May 2026, with room for future enhancements like cloud synchronization and gamification.

Project Milestones Include:

  1. Project Setup & Planning (Week 1–2): Establish project repository, version control, and task tracking. Define final app architecture (MVVM pattern with Room and ViewModel). Confirm tech stack: Kotlin, Room Database, Android Notification Manager, and optional Firebase integration. Deliverable: Development environment configured and documentation initialized

  2. Core Database Design (Week 3–4): Create Room database schema for directives, user preferences, and history tracking. Implement data access objects (DAOs) and entity models. Deliverable: Fully functional local data layer with CRUD operations.

  3. Directive Management System (Week 5–6): Implement directive creation, editing, deletion, and retrieval features. Enable user-defined categories and personalization. Deliverable: Users can view, add, and modify directives through a simple UI.

  4. Notification Scheduling and Action Windows (Week 7–8): Develop system for user-configured Action Windows. Integrate random directive scheduling and delivery using Android notifications. Deliverable: Users receive directives at appropriate, randomized times.

  5. Progress Tracking Dashboard (Week 9–10): Design UI for displaying completed directives, progress statistics, and user preferences. Include analytics features for engagement tracking. Deliverable: Functional progress dashboard connected to local database.

  6. Safety & Moderation Systems (Week 11–12): Implement directive validation, flagging, and reporting tools. Add filters for unsafe or ambiguous content. Deliverable: Functional moderation and risk-mitigation system.

  7. Testing and Quality Assurance (Week 13): Conduct unit and integration testing of database, notifications, and UI components. Evaluate usability and timing accuracy of notifications. Deliverable: Stable, bug-free beta version.

  8. Final Integration & Deployment (Week 14–16): Prepare app for release including icon, splash screen, and onboarding screens. Conduct final presentation and sponsor review. Deliverable: Completed app ready for public release and submission.

This phased approach builds logically, addressing risks through mid-project safety integration and ensuring a robust foundation for post-MVP expansions.
