KIMinder360 Mobile App

Features

Summary: The KIMinder360 app's functional requirements are prioritized into Must-Have (essential for MVP), Should-Have (valuable enhancements), and Could-Have (future expansions) categories. Below is a concise summary of features, including user stories, priorities, estimates, key acceptance criteria, and descriptions. Won't-have features are not present at this time, ensuring focus on achievable deliverables.

Must Have Features

  1. Push Notifications: This feature implements the primary delivery mechanism for KIMinder360’s directives, ensuring that prompts are non-intrusive but consistent. Notifications use Android’s AlarmManager or WorkManager for scheduling. This connects to our domain level requirement of automated situational awareness training by enabling the core functionality of sending out directives to users.

  2. Database of Directives: This feature provides the backbone for directive delivery and tracking. It ensures that all reminders and user interactions pull from a single source. The database works in tandem with push notifications, forming the core of KIMinder360’s directive system.

  3. Category Selection: This feature enhances the app's gamification and allows users to choose directive categories that better match their goals. It supports the domain-level requirement for user customization and scheduling by letting users select only the categories that apply to them.

  4. Active Hours Selection: This feature allows users to customize specific hours during which they wish to receive directives or notifications. The system provides a UI showing all seven days of the week, and each day allows the user to select an active time range. This reduces interruptions outside preferred hours while supporting a balanced schedule. It meets the domain-level requirement for user customization and scheduling by letting users choose when they receive directives.

Should Have Features

  1. Personal Directive Submission: This feature allows users to add personal directives that fit their individual goals or routines. By supporting personal directive creation, users can continue to find value in KIMinder360 even if official development or new directive sets are no longer released. This ensures that the app remains useful and relevant over time, empowering users to sustain their own situational awareness practice indefinitely. This connects to our domain level requirement of user customization by letting users create their own directives that are specific to their situations to create an experience that is best for them. It also ties into our data handling and directive management domain requirement by necessitating that our data structures can handle user created content.

  2. User Engagement Selection: This feature allows the user to select 1 of three engagement levels for interacting with directives going from no engagement to full written response. This allows users to approach the situational awareness training with however much effort and attentiveness that they desire. This connects to our domain level requirement of user customization by letting users decide how much they interact with the directives they are given to match them where they are in their situational awareness journey.

  3. Difficulty Selection: This feature allows users to be able to change the difficulty level of the directives they receive within their category. This creates more depth to the app and a way for users to challenge themselves if that is what they’re looking for. This connects to our domain level requirement of user customization by allowing our users to choose how intense the directives they receive are.

  4. Skip or Delay/Postpone/Bookmark Directive Option: This feature allows users better control for when and how they interact with directives. That way, by offering these options, users can manage their focus and prioritize their tasks. When a user chooses to skip a directive, that directive is archived. When they choose to postpone, the directive is rescheduled for a later time. When they bookmark, the directive is saved for later review. This connects to our domain level requirement of user customization by letting them postpone directives they are not able to complete at the current time and skip directives they have no interest in.

Could Have Features

  1. Location Functionality: Location services expand the capabilities of the KIMinder360 app to allow for more relevant directives that adapt to context and for us to connect users with each other through the app. Implementation is optional in the MVP. This connects to our domain level requirement of automated situational awareness training by encouraging training that is more in depth by connecting users with each other or having them do specific tasks that could only be done in their current location.

  2. Multipart Directives: This requirement adds the feature of specialized multipart directives that build on one another with a set theme. Through this feature we can improve user retention and enjoyment through gamified mechanics while also implementing advanced training that single directives won't allow for. This connects to our domain level requirement of automated situational awareness training by pushing our users to improve their skills even more through chains of directives that build on one another.

  3. Completed Directives List: This feature provides users with a visual record of their progress. It allows them to see which directives they’ve completed and encourages consistent engagement. It would later become a component of the broader “Dashboard” that displays user progress or performance trends. This connects to our domain level requirement of directive management and data handling by forcing us to create in depth databases that keep track of user activity and directive history.

  4. Monetization: This feature enables future revenue generation by allowing users to buy new directive categories, packs, or additional features such as themes or extra cloud storage for sharing directives online. Monetization would be handled securely through the respective app store’s purchase system(s) and integrated within the user interface as optional enhancements. This connects to our domain level requirement of Scalability and growth by giving us the option to develop new content in the form of directive packages and categories that the user can purchase.

  5. Leaderboards: This feature allows users to compete in completing directives and be displayed in a leaderboard among peers or household members. The leaderboard would display the total number of directives that the top users have completed. This connects to our domain level requirement of automated situational awareness training by implementing a gamification mechanic that will encourage the user to try harder directives and complete more in any given period of time.

  6. Cloud Database Shared Directives: This feature provides centralized data management for all information with directives. By using a secure cloud database, directives are accessible and synced across different devices and accounts. This system allows for shared access among users, giving them control to collaborate with chosen users. This connects to our domain level requirement of scalability and growth by letting our community think of directives that our development team could not and contributing them to the community database where our content will grow naturally.

These requirements ensure the app meets expectations for functionality, engagement, and safety, with "Must Have" as the MVP foundation, "Should Have" for enhancements, and "Could Have" for growth pathways.
